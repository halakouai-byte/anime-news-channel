# Runbook — راهنمای بحران و عملیات

## توقف کامل انتشار (فوری)

سریع‌ترین راه: در گیت‌هاب Settings → Secrets → Actions، `TELEGRAM_BOT_TOKEN`
را حذف یا عوض کنید — ورک‌فلوها بدون توکن fail می‌شوند و هیچ پستی نمی‌رود.
بعد ورک‌فلوهای `publish.yml` و `sweeper.yml` را در Actions → Disable کنید.
(حذف Secret برگشت‌پذیر است؛ دوباره همان نام را با مقدار تازه بسازید.)

## حذف یک پست اشتباه از کانال

1. در تلگرام، پست را حذف کنید (ادمین کانال).
2. در `data/archive.jsonl` رکورد آن پست را پیدا کنید و `status` را به
   `deleted-manual` تغییر دهید تا بازبینی بداند چرا `message_id` دیگر نیست.
3. اگر اشتباه از بانک نام/قالب بود، همان بانک را اصلاح کنید تا تکرار نشود.

## چرخش توکن‌ها

### تلگرام (`TELEGRAM_BOT_TOKEN`)
1. در BotFather با `/revoke` توکن تازه بگیرید.
2. در GitHub Secrets مقدار `TELEGRAM_BOT_TOKEN` را به‌روز کنید.
3. یک انتشار دستی آزمایشی (Actions → Publish → Run workflow) انجام دهید.

### PAT دیسپچ (`GITHUB_DISPATCH_PAT`) — انقضا ۲۱ نوامبر ۲۰۲۷
1. پیش از انقضا، در GitHub → Settings → Developer settings → Personal access
   tokens → Fine-grained tokens، یک PAT تازه با همان scope بسازید
   (فقط ریپوی `anime-news-channel`: Actions Read and write + Contents Read-only
   + Metadata Read-only).
2. در Cloudflare → Workers → `anime-news-detector` → Settings → Variables:
   مقدار `GITHUB_DISPATCH_PAT` را به‌روز کنید (مقدار فقط از stdin/صفحه امن
   وارد می‌شود، هرگز در فایل یا چت).
3. PAT قدیمی را revoke کنید.

## نشت سکرت (مشکوک یا قطعی)

1. **توقف:** فوراً انتشار را متوقف کنید (بخش بالا).
2. **خبر به مدیر:** بی‌درنگ اطلاع دهید؛ بی‌صدا فایل را حذف نکنید و ادامه ندهید.
3. **چرخش:** توکنِ لو رفته را revoke و تازه کنید (بخش بالا).
4. **پاکسازی تاریخچه:** اگر سکرت در تاریخچه git رفته، تاریخچه باید بازنویسی شود
   (با مدیر هماهنگ کنید — force-push روی `main` مسدود است).

## فید از کار افتاد

- اگر یک فید چند اجرا پشت سر هم خطا داد، در `logs/fetch-log.md` دیده می‌شود؛
  بقیه ۷ منبع ادامه می‌دهند (هیچ وابستگی تک‌منبعی نیست).
- اگر ANN یا MAL آدرس فید را عوض کرد، آدرس تازه فقط وقتی نوشته می‌شود که با
  fetch زنده تایید شده باشد — آدرس حدسی ممنوع است.

## تلگرام ۴۲۹

- `publish.py` فقط یک بار با `retry_after` retry می‌کند، بعد خبر در صف می‌ماند
  تا اجرای بعد. هرگز retry پشت سر هم نکنید.
- اگر ۴۲۹ تکرار شد، فاصله‌گذاری یا حجم صف را در بازبینی هفتگی بررسی کنید.

## کامیت state بعد از ارسال شکست خورد

- ورک‌فلو یک بار `pull --rebase` + retry می‌کند؛ بار دوم هم شکست خورد، اجرا
  با خطا تمام می‌شود و اجرای بعدی خبر را از روی `seen` + آرشیو تشخیص می‌دهد و
  دوباره نمی‌فرستد (گارد state پیش از هر ارسال).
- اگر `state.json` و `queue.json` ناهمگام شدند، `state.json` مرجع نهایی است.
